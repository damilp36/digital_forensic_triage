    Report: does each CIC-2017 weakness repeat on other data? (same tables, 3 corpora side by side)

W1  Isolation forest barely detects P1 attacks
    Saw: AUROC 0.71 overall, ~0.50 on P1; only 4.5% of P1 flows become alerts (det_p1_alerted
         0.045), so workload rests on ~43 P1 alerts per seed -> the +/- 0.33 spread. Late test half
         misses Bot and Infiltration almost entirely (P1 alerting 1.0 early vs 0.04 late).
    Do: (a) run main with detector: {type: autoencoder} (AUROC 0.90 on CIC-2017) and compare;
        (b) sweep alert threshold theta 0.90/0.95/0.99 and report P1 recall vs alert volume;
        (c) add a periodic recalibration variant for the time-shift probe.
    Report: "unsupervised detector choice bounds triage quality; rules cannot rescue missed P1".
    Decide: primary detector for the paper = autoencoder if it holds on NetFlow.

W2  SHAP predicates add nothing on CIC-2017
    Saw: Abl-no-SHAP-predicates = XTriage on every metric; rule fidelity to SHAP ~0.06
         (rules pick traffic bins that are not among the detector's top-5 reasons).
    Do: (a) check whether this repeats on NetFlow (N1); (b) run a "predicates + band only"
        representation (no raw bins) to see whether SHAP alone carries triage signal;
        (c) try top_k 3 and 10.
    Report honestly: explanation-augmented rules are not automatically more faithful or better;
        oracle labels drive rules toward features the detector does not use.

W3  Guard works but is blunt
    Saw: 71% of alerts contested, mostly because only the catch-all rule fired; precision ~0.003;
         still catches 60-85% of P1 events a rule would have dismissed. It is the whole gain.
    Do: (a) replace "default rule fired" with "rule precision on tune < tau" (store per-rule tune
        precision in the ruleset); (b) plot catch rate vs contested rate as tau / p3_max_q vary;
        (c) add this variant to VARIANTS in src/xtriage/eval/experiments.py.
    Target: contested rate < 30% with catch rate >= 60%.

W4  Rules are brittle to features the detector ignores
    Saw: setting destination port to 443 leaves the score unchanged (dq ~ 0) but changes the fired
         rule for 78% of attack alerts and the tier for 36%; timing x5 demotes 19% of P1.
    Do: (a) variant that drops port bins from z (or maps port -> service class);
        (b) variant that only allows rule conditions on the alert's top-k SHAP features;
        (c) rerun probe_evasion on both and on NetFlow (L4_DST_PORT).
    Report: tier flip rate under perturbation, before vs after.

W5  Rules collapse under label noise
    Saw: eta = 0.1 -> P1 F1 0.79 -> 0.17, workload 0.03 -> 0.58 (P1 is rare, few flips erase it).
    Do: (a) bagged RIPPER (e.g. 11 bootstraps, majority vote) or minimum support for P1 rules;
        (b) rerun the eta sweep (0, 0.05, 0.1, 0.2) for plain vs robust.
    Report: noise level at which P1 F1 drops below 0.5, plain vs robust.

W6  Retraining the detector changes the explanations
    Saw: top-5 Jaccard 0.27 across detector seeds (vs 0.97 across background sets), Kendall tau
         0.69. Phase 2 hypothesis "near-threshold alerts are less stable" NOT supported (low band
         0.33 vs high band 0.20).
    Do: (a) n_estimators 100 -> 300 -> 1000 and remeasure Jaccard; (b) repeat for autoencoder.
    Report: as a limitation of per-model SHAP for forensic evidence; update the hypothesis text.

W7  "Shortcut" features are not shortcuts here
    Saw: removing Destination Port and Init_Win_bytes_* improved AUROC 0.71 -> 0.75.
    Do: repeat on UNSW-NB15 with L4_DST_PORT, MIN_TTL, MAX_TTL (TTL is a known UNSW-NB15 artefact).
